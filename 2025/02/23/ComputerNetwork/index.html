什么是Internet

Internet： （1）由节点和边组成的，按照协议通讯的，多个这样的网络组成的，遍布全世界的网络。 （2） 应用层上的应用以及以下所有提供通讯的基础设施

  1. 节点：主机节点（方的）（edge system）硬件，操作系统和跑在上面的软件

    ​ 交换节点（圆的） 数据链路层的交换机，网络层的路由器，更高层的网络均衡负载设备

  2. 边：方的和圆的连接的（access），圆的和圆的连接（backbone）

  3. 协议： 对等层实体交互的一簇标准。协议规定了 报文格式，次序，以及所采取的动作。

端（Edge）

总体：edge-access-core

  • edge：上述内容

  • access 连接edge和core

  • core：传输数据。 可以把core抽象成一个巨大switch开关一个端通过核心连接网络上另一个端。但实际上是由一个又一个的分布式系统连接的

Edge ：端系统运行应用程序（web，email），处于网络边缘

​ 两种模式：cs（Client/Server），在CS模式中，网络中的设备被分为两种角色：客户端（Client）和服务器（Server）。客户端发起请求，服务器处理请求并返回响应。客户端和服务器通常具有不同的功能和资源，客户端通常依赖服务器提供的服务。弊端可扩展性差

​ p2p（Peer to Peer），所有参与者都被视为对等节点（Peer），每个节点既是客户端又是服务器。节点可以相互提供服务和资源，而无需依赖中央服务器。每个节点既可以发起请求，也可以响应其他节点的请求。

​ 采用网络设施的面向连接服务:

TCP(Transmission Control Protocol ) 传输控制协议，面向连接的服务。

TCP提供的服务：1）不失序，不乱序，不丢失。。。 发出去的原原本本的收到的

​ 2）流量控制

​ 3）拥塞控制

核心（Core）

作用：数据交换

形式：电路交换（circuit switch），分组交换（packet switch）

  • 电路交换

    • 通过信令系统，通过频分、时分、码分、波分等方式将网络资源（如贷款） 分成片（piece）。需要维护连接

    • eg：通过时分多路复用，将带宽分成24个时槽，用户只用到其中一份 eg 1.536 mbps-》64k/s [图片](/Users/tianjiashun/Pictures/截屏/截屏2025-02-17 14.50.20.png) 如图，计算

    • 优点：资源独享， 保证性能

    • 缺点：资源浪费（对于计算机来说，资源的请求一般是突发的）

    • 应用：电话网

  • 分组交换（packet switch）

    网络资源被分成packet，获取全部带宽，将packet全部储存再转发。

    • 实现方式：（全局的）存储+（局部的）转发

      通过统计多路复用，也是通过划分时间片的方式，一段时间穿a一段时候穿b一段时间空闲。

      路由：决定原到目标主机的路径。路由表由算法生成

      转发：将分组通过链路转移到下一个目标。。

    • eg. [图片](/Users/tianjiashun/Pictures/截屏/截屏2025-02-17 15.23.38.png) 如图，在一定的带宽，每个用户使用10kbps线路交换只能服务到10个用户。对于分组交换，有10%的概率用户使用，在35个用户使用的情况下，99.6%的概率用户是可以正常使用。

    • 优点：共享性，不需要维护连接

    • 缺点：丢包（如队列拥堵导致下一个排队的分组被路由器丢弃）

    • 应用：计算机网络

协议层次与服务模型

​ 协议：对等层实体交互的一簇标准。协议规定了 报文格式，次序，以及所采取的动作。

​ 服务：是功能的一部分（功能强大体现在提供的服务）。

​ 分层体现在，上一层通过层间结构利用下层提供服务，为上层提供更好的服务。下一层是上一层的提供者，上一层是服务用户。这意味着一个服务可能有很多个服务用户，（类比顺丰快递，顺丰要服务好多个用户，并提供寄快递等服务）层间接口SAP(如socket API)+服务原语（如创建socket函数）。上层向下层传递数据单元SDU，并加入接口控制信息ICI包装成PDU传递给下一层。传递中根据大小会出现切片Slicing（比如，过大的数据单元会被切成一个一个小的，并加入ICI；过小的数据单元会被并成一个大的数据单元传送。最终出现一对一，一对多，多对一的局面）。

​ 协议VS服务：协议是横向的，是对等层之间；服务是垂直的，上一层通过下一层提供的服务，扩展本层的能力，并向上层提供服务（上层服务依靠的是下面所有层的服务，不是当一个层次的）。

​ 不同层的SDU还有不同的称呼，如应用层的消息message，传输层的分组/数据报（segment），网络层的分组\ip数据包、物理层的帧（frame）

原理

应层的作用：通过网络基础设施提供的服务，应用进程彼此通信。

网络应用的体系结构：C/S , P2P, 混合型

  • C/S：服务器:

    • 一直运行

    • 固定的IP地址和周知的端 口号（约定）

    • 扩展性：扩展性差

      客户端:

    • 主动与服务器通信

    • 与互联网有间歇性的连接

    • 可能是动态IP 地址

    • 不直接与其它客户端通信

  • P2P ：

    • （几乎）没有一直运行的服务器
    • 任意端系统之间可以进行通信
    • 每一个节点既是客户端又是服务器
    • 自扩展性新peer节点带来新的服务能力，当然也带来新的服务请求
    • 参与的主机间歇性连接且可以 改变IP 地址
    • （缺点）难以管理

  • 混合型

    • 例子： 即时通信 在线检测：集中 当用户上线时，向中心服务器注册其IP地址 用户与中心服务器联系，以找到其在线好友的位置。

进程间通信

​ 在同一个主机，进程与进程之间通信，依赖操作系统提供的api即可；不同主机间，通过交换报完（Message）来通信：1)使用OS提供的通信服务（socketAPI)

2)按照应用协议交换报文。3）注：P2P架构下，也有客户端进程和服务端进程之分

分布式进程通信

​ 三个问题：如何寻找到服务用户，如何区分服务，如何使用传输层提供的服务，实现应用进程的报文交换，实现应用。

  • 问题一：寻址

    ​ 进程为了能接受和发送报文，必须有一个标识：ip+TCP or UDP+端口号(分为用于常见服务的知名端口号，用于特定的应用或服务使用的注册端口号，用于客户端应用程序临时使用或私有的动态私有端口号）。本质上，一对主机进程之间的通信由2个端结点构成.

  • 问题二：传输层向应用层提供服务，需要穿过层间的信息

     层间的信息包括：源主机地址及端口，目标主机地址端口，SDU

​ 传输层实体（tcp或者udp实体）根据这些信息进行tcp报文段（udp数据报）的封装：源端口号，目标端口号，数据等；将ip地址往下文ip实体，用于封装ip数据包：源ip目标ip。

​ tcp(建立连接）为保持会话，提升操作系统管理效率引入socket（本质是一个整数，由ip地址，协议，端口号合成，是一种文件操作符）,代表着会话关系。操作系统内部维护一张表（包含:源ip，源port，目标ip，目标端口，状态）

​ udp:是无连接不可靠的服务，socket由源ip地址，源ip端口。udp Socket的特点是，无需建立连接；每个报文独立传输且前后报文可能给不同的分布式进程（意思就是同样的端口多个数据报往不同的ip发送）。注：传输时，仍然需要加入目标ip端口号。

  • 问题三：使用传输层提供的服务实现应用

应用层协议定义了：运行在不同端系统上的应用进程如何相互交换报文

交换的报文类型：（请求和应答报文各种报文类型的）语法，报文中的各个字段及其描述字段的语义，（即字段取值的含义） 进程何时、如何发送报文及对报 文进行响应的规则 。而应用协议仅仅是应用的一个组成部分。

​ (首先，应用协议时应用的一部分，应用实体：仅含协议)

应用层需要传输层提供哪些服务：例如拥塞，流量控制，可靠传输，安全（tcp，udp都是明文传输）。有一些协议跑在tcp之上，有些跑在udp之上。

响应时间模型

​ 往返时间RTT:一个小的分组从客户端到服务器，在回到客户端的时间（传输时间忽略）

http报文

http报文分为：请求报文（request）和响应报文（response）。

  • request：请求行（GET,POST,HEAD)+首部行+内容
    • GET：输入通过请求行的URL字段上载。形式可以是：(参数加参数值).com/wd=xxx&cl=3
    • POST：网页通常包括表单输入，包含在实体主体中的输入被提交到服务器。
    • HEAD：仅提供响应头部，通过头部信息建立索引等。
    • 1.1又加入了 put和delete：将将实体主体中的文件上载 到URL字段规定的路径；删除URL字段规定的文件。
  • response：状态行，首部行（）数据
    • 状态行：状态码+解释
      • 200：ok 请求成功，请求对象包含在响应报文的后续部分
      • 301：Moved Permanently 请求的对象已经被永久转移了；新的URL在响应报文的Location（首部行中指定）客户端软件自动用新的URL去获取对象。
      • 400：Bad Request 一个通用的差错代码，表示该请求不能被服务器解读
      • 404 ：Not Found 请求的文档在该服务上没有找到
      • 505：**HTTP Version Not Supported **http版本不支持。
      • ……
    • 首部行：包含参数和参数值
      • length-width
      • keep
    • 数据：比如http文件

cookie，web缓存

​ tcp不维护报文的边界：服务器不存储信息。引入cookie机制，满足诸如购物网站的需求。

​ cookie：服务器将cookie存储在head中，客户端接受后将cookie保存在本地，下次请求时会将cookie加入到request中。

​ 注：初次访问网站时服务器会生成cookie。

​ 特点：可以实现用户登记，网上购物等，会带来隐私安全问题。

web缓存 在本地局域网内部署web缓存服务器，下次客户端再请求内容的时候，就可以先去找缓存服务器，如果没有再去remote-server远端服务器请求。

​ eg。「省略，待补充」

优点：通过命中（hit），减少多段rtt，可以大幅优化用户体验，减少服务器压力，减少网络压力。

问题：remote服务器如果更改，会导致和缓存服务器内容不一致。

​ 解决方法：如果遇到信息不一致，缓存服务器向remote发送get请求head（包含 if-modify《time》）仅对比，不一致再去更新。

dns介绍

​ 域名解析系统，位于应用层，运行在UDP之上端口号为5。用于域名到ip地址的互查的应用服务。

作用：

​ 域名解析：将域名转换为 IP 地址，确保客户端能够正确连接到服务器。

​ 反向解析：通过 IP 地址查找对应的域名（用于邮件验证、日志分析等）。

​ 管理网络资源：通过各种 DNS 记录（如 A 记录、MX 记录等）帮助配置和管理互联网资源。

域名空间

DNS命名空间采用分层结构，从上到下依次是：

  • 根域（Root）：位于层级结构的最顶端，通常用 .（点）表示。
  • 顶级域（TLD, Top-Level Domain）：
    • 通用顶级域（gTLD，如：.com、.org、.net、.edu）
    • 国家/地区代码顶级域（ccTLD，如：.cn、.uk、.jp）
    • 基础设施顶级域（如：.arpa）
  • 二级域（Second-Level Domain, SLD）：紧随TLD之后的部分，如 google.com 中的 google。
  • 子域（Subdomain）：在二级域之下的部分，例如 mail.google.com 中的 mail。
  • 主机名（Host Name）：最底层的部分，指向具体设备或服务器，如 www.google.com 中的 www。
  • DNS名称是从 最底层（左侧）到最顶层（右侧） 解析的，根域通常可以省略（但严格来说是存在的）。

递归查询/迭代查询

假设用户访问 www.example.com：

  1. 浏览器缓存：浏览器会先查找本地缓存是否已有 www.example.com 的 IP 地址。

  2. 操作系统缓存：如果浏览器缓存没有匹配项，操作系统的 DNS 缓存会被查询（如 Windows 的 ipconfig /displaydns）。

  3. 本地 hosts 文件：操作系统会检查 /etc/hosts（Linux/macOS）或 C:\Windows\System32\drivers\etc\hosts（Windows）是否有匹配的 IP。

  4. 本地 DNS 服务器（ISP 提供）：

    • 若本地缓存无结果，查询递归 DNS 服务器（通常是 ISP 提供的）。
    • 递归 DNS 服务器会检查其缓存，若无结果，进行递归查询：
      1. 根 DNS 服务器（.）：指向 .com 顶级域（TLD）服务器。
      2. TLD 服务器（.com）：指向 example.com 的权威 DNS 服务器。
      3. 权威 DNS 服务器：返回 www.example.com 对应的 IP 地址（如 192.0.2.1）。

  5. 返回 IP 地址：

    • 递归 DNS 服务器将 IP 地址 192.0.2.1 发送给客户端。
    • 浏览器使用 192.0.2.1 访问服务器。

  6. 弊端：

    • 根服务器 → 顶级域名服务器（TLD） → 权威 DNS 服务器 逐级查询，每个查询都要消耗计算资源和网络带宽，导致递归 DNS 服务器的压力增大。
    • 如果某个上游服务器响应慢或丢包，会导致查询延迟，影响用户体验。
    • 如果通信链路被劫持（如 ISP 劫持）或 DNS 服务器被污染，可能会返回错误的 IP 地址，导致用户访问钓鱼网站或被重定向到广告页面。

  7. 目前 DNS 查询仍然遵循 从根到权威 DNS 服务器 的逻辑，但做了许多优化，以减少递归查询的弊端：

    • 递归查询（Recursive Query）：DNS 服务器会 代替客户端完成整个查询，直到获得最终 IP 地址。
    • 迭代查询（Iterative Query）：DNS 服务器不会直接完成整个查询，而是返回下一步查询的服务器信息，由本地 DNS 解析器自己继续查询。
    • 缓存（cache）：设立本地名字服务器，当一个主机发起一个dns查询时，离开本地后先去本地名字服务器查找。如果本地名字服务器不能解析 名字时，联系根名字服务器 顺着根-TLD 一直找到权威名字服务器。最终提高查询效率。
      • 可能出现的问题：缓存结果可能和权威资源记录不一致？可以设置TTL（time to live)（默认两天）缓存是为了性能，删除是为了一致性

    源ip+源端口+长度+校验和 （共4B，32位）

    ​ 校验和：当目标主机收到udp会检测校验和本身和校验和非范围 是否符合EDC的范围 （EDC 错误检测码），如果错误，直接丢弃。（出错的表现为丢失）。但是仍有一定的概率检验范围和checksum相同。

    • 检验和检查方法：进位回滚：整个报文的特定部分（如 IP 头部、TCP 伪首部 + TCP 负载等）拆分成 16 位（2 字节） 的片段，依次进行相加。如果报文长度不是偶数，则最后一个字节会补零。由于累加时可能会超出 16 位（产生第 17 位的进位），进位需要回滚，即将最高位的进位加回到最低位 这个过程会重复，直到没有进位为止。将结果存到checksum段。

  • 优势：udp头部数据小（tcp20B），发送压力小：传输层向网络层穿的时间=最终发送到网络的时间。

可靠传输的机制的原理

​ rdt：reliable data transmission 可靠数据传输。

rdt1.0：（假设用于传输的这个 reliable channel没有问题，只是数据有错位，如1变0，sum不合）引入 ack和nck（acknowledge / negative）如果收到了发送一个ack，没有发送nck（数据包送到receive一方，检验不通过，丢掉？）。

​ 问题：如果ack/nck 有问题（ack变成nck，或者ack不知道变成什么东西）

​ rdt1.1:将每个数据包加入序号。eg：发送p0，发送ack，如果p0没收到，继续发送p0，收到为止，如果对面ack没收到，继续发送p0，接收方发现重复（duplicate） ，舍弃并继续发送ack，直到对方收到ack 发送p1。

​ rdt2.0: 取消nck，引入ack编号，通过上一个ack的正反馈来做下一个ack的判断。eg。如果ack0发送成功，但是又发送ack0，发送方认为p1没有收到，重发p1，收到ack1为止。

​ rdt 3.0（假如这时channel出现了拥塞，导致丢包）

引入超时重传机制。发送方在发送一个分组时设立一个timer，发送方发送p0之后等待ack，但是ack由于网络拥塞，导致ack被路由器丢弃。

timer一般设置为比rtt大的数，如果在超时时间内收到ACK，说明数据成功传输，发送方继续发送下一个数据包。如果在超时时间内没有收到ACK，发送方会重新发送该数据包，并重新启动超时计时器。

超时重传所带来的一些问题：1）timer时间的设定

  • 过短：可能会导致不必要的重传，增加网络负载。
  • 过长：数据丢失时会等待过长时间，降低传输效率。

2）由网络影响所导致的问题

网络拥堵：超时重传可能会导致网络负载增加，加剧拥堵情况，因此需要结合拥塞控制策略。

误判丢包：如果网络延迟较大，发送方可能会误判数据包丢失，提前触发重传，导致重复数据传输。

​ 这种发送一个确认一个的形式叫做stop-and-wait。缺点，效率太低：假设1gbps的带宽，rtt30ms，但是穿出所占据的时间自由2*8微秒。利用率不足1%。

引入pipeline流水线，一次发送多个待确认的packet，多次发送多次请求。每个包必须要用2^n位表示分组序号
双方加入缓存机制：

  • 发送方缓冲：未得到确认，可能需要重传；
  • 接收方缓存：上层用户取用数据的速率≠接收到的数据速率；接收到的数据可能乱序，排序交付（可靠）
  • 设置缓存的目的：发送方发送的速率和接收方接受的速率不一样。

两种通用的流水线协议：back-to-n 和 selective repeat

滑动窗口（sliding window）：

​ 如果一对一：stop-and-wait

​ 如果大于一对一：back-to-n

​ 如果大于一对大于一：selective repeat

概论

​ 对上层到来的tcp or udp 报文进行封装成ip报往下传。位于计算机网络的核心（core）部分，作用是存储转发和路由。

​ 转发：决定通过一个端口向另一个端口进行发送。局部的。

​ 传统方式：基于目标地址+转发表

​ SDN：基于多个字段+流表。(实现了block，泛洪，修改字段)

​ 控制机器上一些如防火墙的软件 按照南向接口把算出来的流表交给SDN的分组交换机。分组交换机对到来的分组的头部信息匹配它的多个字段做匹配， 按照表象的action做动作 。

​ 路由：决定按照哪条路径发送，通过路由表（路由器算）转发。

转发是数据平面，转发是控制平面。

​ 服务模型（类型）：best effort 尽力而为，就是什么也不保障

路由器的工作原理

​ 路由器，转发和路由。

​ 抽象成(router) input(port)-》(high-speed switching) fabric-》output

转发表计算出来下载到输入端口，通过fabric决定往哪个output port发。

input：line termination+ link layer protocol + lookup forwarding queue

​ line:物理层bit级接收。 link：链路层协议动作、解封装

​ queue：分布式交换 根据数据报头部的信息如：目的地址 ，在输入端口内存中的转发表中查找 合适的输出端口（匹配+行动）

  • 类型：

    • 基于目标的转发：仅仅依赖于IP数据 报的目标IP地址（传统方法）
    • 通用转发：基于头部字段的任意集合 进行转发。

  • 输入端口缓存：

    • 当交换机构的速率小于输入端口的汇聚速率时，在输入端口可能要排队。(如果不缓存，下一个到来的分组由于缓存溢出造成丢失)
    • head-of-line blocking 排在对头的数据报阻止了队列中其他数据报向前移动。（输出端口竞争 都向往一个地方发送）。

  • 交换结构

    • 将分组从输入缓冲区传输到合适的输出端口
    • 交换速率 (略)
    • 三种类型（memory，bus，crossbar）

  • memory ：通过内存交换

    • 分组拷贝到内存，cpu提取地址查表、转发。一次一分组，速率收到内存带宽的限制。
    • bus：数据报通过共享总线，从输入端 口转发到输出端口。一次一分组，分组有竞争，交换速度还要受限于总线。适用于企业网
    • crossbar：同时并发转发多个分组，克服总线带宽 。适合骨干网。

  • 调度算法：

    • 当数据报从交换机构的到达速度比传输速率快就需要缓存，由调度规则决定那些数据先被发送。
      • fifo（fgfs）：先到的先服务，来不到的直接丢弃
      • 优先权，发送最高优先权的分组（可能取决于标记或者其他的头部字段）
      • rr（round robin）(前提是有几类等级不同的)循环扫描不同类型的队列，发送完一类的再发送一类的。（轮回）
      • weighted fair queuing（加权公平排队），每类赋予不同的权重，每个队列得到的服务时间和权重成正比，每个类在每一个循环获得不同权重的服务量。

各字段含义

  1. 版本（Version, 4 bits）
    指定 IP 协议的版本，例如 IPv4（值为 4）或 IPv6（值为 6）。
  2. 首部长度（Header Length, 4 bits）
    表示 IP 头部的长度，以 4 字节（32 位）为单位。例如，值为 5 表示头部长度为 5 × 4 = 20 字节。
  3. 服务类型（Type of Service, 8 bits）
    主要用于 QoS（服务质量）控制，包含不同的优先级、吞吐量、时延等。
  4. 总长度（Total Length, 16 bits）
    表示整个 IP 数据报的长度（包括头部和数据），最大 65535 字节。
  5. 标识（Identification, 16 bits）

​ 用于切片

  1. 标志（Flags, 3 bits）

  2. 片偏移（Fragment Offset, 13 bits）

​ 用于切片

  1. 生存时间（Time to Live, TTL, 8 bits）
    控制数据包的生存时间，每经过一个路由器，该值减少 1，变为 0 时丢弃数据包，防止死循环。

  2. 协议（Protocol, 8 bits）
    指示该 IP 数据报携带的上层协议，例如：

  • 1：ICMP
  • 6：TCP
  • 17：UDP
  1. 头部校验和（Header Checksum, 16 bits）
    检验 IP 头部是否损坏，接收方验证后可发现错误。
  2. 源 IP 地址（Source Address, 32 bits）
    发送方的 IP 地址。
  3. 目的 IP 地址（Destination Address, 32 bits）
    接收方的 IP 地址。
  4. 可选字段（Options, 可选）
    用于测试、调试或安全功能，可变长，常见的选项包括时间戳、记录路径等。
  5. 数据部分（Data, 变长）
    负载数据，通常是 TCP 或 UDP 数据。

切片

​ 当数据报较大，超过链路的 MTU（最大传输单元，如以太网 MTU 通常为 1500 字节）时，IP 层会对其进行分片。这些分片都会共享相同的标识值，以便接收端能够将它们正确地重组回原始数据报。

  • 标识字段（identifier）是 IP 数据报的一个 16 位字段，用于唯一标识同一个数据报的所有分片。
  • 偏移量

​ 指定当前分片在原始数据报中的偏移位置，以 8 字节为单位。用于标识哪些片属于哪一个数据报。

IP 片偏移以 8 字节（64 bit） 为单位，主要是因为：

  1. 节省存储空间：用 13 位 偏移字段就能支持 65535 字节的 IP 数据报。

    片偏移字段是 13 位，如果按 1 字节 为单位，最大偏移量是：

    213−1=8191（字节）2^{13} - 1 = 8191（字节）213−1=8191（字节）

    这样，只能支持最多 8191 字节的 IP 分片，但 IP 允许最大数据报长度 65535 字节（Total Length 字段是 16 位）。

    采用 8 字节单位，最大偏移量变为：

    8191×8=65528（字节）8191 * 8 = 65528 （字节）8191×8=65528（字节）

    这样就能支持 65535 字节的数据报（加上 IP 头部）。

  2. 提高硬件处理效率：网络设备和 CPU 处理 8 字节对齐的数据更高效。

  3. 确保数据分片正确重组：保证所有 IP 片都能完美对齐拼接，避免额外的对齐计算。

  • 标志位
    • 控制数据报是否分片以及是否是最后一个分片：
      • 第一位（保留）：必须为 0。
      • 第二位（DF, Don’t Fragment）：1 表示不允许分片，0 表示允许分片。
      • 第三位（MF, More Fragments）：1 表示后面还有分片，0 表示这是最后一个分片。

ip会根据上层协议如tcp 或者udp 采取一些行动。

协议 IP 分片丢失后果 解决方式
TCP 数据段无法重组，导致数据段丢失 依靠超时重传或快速重传，重发整个 TCP 段
UDP 数据报无法重组，直接丢弃 无内置重传，应用层自行

子网和ip地址

​ 简记：互联网是网络的网络，必然有一个网络是一个网络的子网。

​ 怎么区分子网：

  1. 传统ABCD类分类：

    • 定义： 传统的IP地址分为A、B、C三类（以及后来的D和E类），根据IP地址
      前几位固定标识符来划分。
      • A类：第一个字节为0开头。
      • B类：第一、二个字节为10开头。
      • C类：前三个字节为110开头。
    • 用途： 主要用于确定网络号和主机号的长度，适用于不同规模的网络。
    • 特殊网：子网部分全为零，本网络。 主机部分全为零，本主机。主机部分全为一，广播地址，这个网络的所有主机。127.0.0.1本地环回地址，

  2. 现代基于前缀长度的分段方法（如CIDR）：

    ​ 根据IP地址前缀的位数来划分网络号和主机号。

  • 网络地址 (Network Address)

    • 定义：网络地址是IP地址的前半部分，表示特定网络中的所有主机（设备）的共享地址。网络地址指示一个特定的网络段或子网，通常由IP地址的高位（根据子网掩码决定）组成。
    • 作用：网络地址用来标识网络本身，告诉路由器或其他设备数据包的目标网络是哪一块区域。网络地址在同一个网络中的所有设备都应该是相同的。它不代表单个设备，而是整个网络。
    • 举例： 假设某个IP地址是 192.168.1.15，并且子网掩码是 255.255.255.0。在这种情况下，网络地址是 192.168.1.0。这表示整个 192.168.1.0/24 网络内的设备。
      • 网络地址：192.168.1.0 （网络部分）
      • 主机地址：15 （主机部分）

  • 主机地址 (Host Address)：

    • 定义：主机地址是IP地址的后半部分，表示网络内特定主机（设备）的唯一标识。主机地址区分了同一网络中不同设备的身份。它通常由IP地址的低位部分组成。
    • 作用：主机地址用来标识网络中的具体设备。每个设备在它所属的网络中应该有一个唯一的主机地址。
    • 举例： 继续使用前面的例子，IP地址 192.168.1.15 的主机地址是 15。这个地址唯一标识在 192.168.1.0 网络中的某个特定设备。

  • 网络地址和主机地址的关系

    • 一个完整的IP地址,例如 : 192.168.1.15

    可以分为两部分：

     - 网络地址：由IP地址和子网掩码确定的网络标识部分。
 - 主机地址：属于该网络中的设备标识部分。

通过子网掩码，我们可以知道哪些位是网络地址，哪些位是主机地址。子网掩码的作用就是将IP地址分成网络部分和主机部分。

补充：子网掩码的计算步骤：

  1. 确定网络号位数：

    • 根据所需的网络规模或前缀长度（如/24）来决定网络号占用多少位。

  2. 将这些位设为1，其余设为0：

    • 在32位中，前面的n位设为1，后面剩余位设为0。

  3. 将二进制掩码转换为点分十进制形式：

    • 将32位二进制数分成四个8位部分，每个部分转换为十进制数值，用点分隔开。

如何获取ip地址

​ 手动分配，dhcp（Dynamic Host Configuration Protocol）

​ dhcp:允许主机在加入网络的时候，动态地从服务器那里获 得IP地址：

流程：

DHCP Discover（发现）

  • 过程：当主机（如电脑）第一次连接到网络时，它不知道自己的IP地址，也无法与网络上的其他设备直接通信。此时，主机会向网络广播一个 DHCP Discover 消息，询问是否有DHCP服务器可以为它分配IP地址。
  • 协议：广播消息（UDP协议）发送到地址 255.255.255.255，端口 67。
  • 目的：让DHCP服务器知道该主机需要一个IP地址，并且它是一个新的请求者。
  1. DHCP Offer（提供）

  • 过程

    ：DHCP服务器接收到DHCP Discover消息后，会选择一个可用的IP地址，并向该主机发送一个 DHCP Offer消息。这个消息包含：

    • 提供的IP地址。
    • 子网掩码。
    • 默认网关地址（如果有）。
    • DNS服务器地址（如果有）。
    • 租约时间（即IP地址有效期）。

  • 协议：服务器将消息广播到网络，目标是主机的MAC地址，源端口是 67，目标端口是 68。

  • 目的：让主机选择其中一个DHCP服务器提供的IP地址。

  1. DHCP Request（请求）

  • 过程

    ：主机接收到一个或多个DHCP Offer后，选择一个最合适的（通常是第一个收到的）并向该DHCP服务器发送

    DHCP Request

    消息，表示接受这个IP地址并请求配置。

    • 在此消息中，主机会表明它已经选择了哪个DHCP服务器的Offer。
    • 该请求是广播的，其他DHCP服务器如果仍然发送了Offer也会被告知，防止冲突。

  • 协议：广播消息，目标是 255.255.255.255，端口 68。

  • 目的：确认选择了某个IP地址，告知DHCP服务器。

  1. DHCP Acknowledge（确认）
  • 过程：DHCP服务器收到DHCP Request消息后，会向主机发送一个 DHCP Acknowledge消息，确认主机已经成功获得了IP地址并且可以使用。
    • 此消息包含：确认的IP地址、子网掩码、网关、DNS等配置。
  • 协议：DHCP服务器回应主机，使用 UDP 协议，源端口 67，目标端口 68。
  • 目的：正式确认IP地址已分配给主机。

在这个过程中，主机成功从DHCP服务器获取了一个动态IP地址，并且可以开始与其他网络设备通信。

路由聚集、路由通告、路由算法

  • 路由聚集：将多个连续的 IP 地址范围合并成一个更大、范围更广的地址块，以便路由器在路由表中只保存一个聚合后的条目，而不是多个单独的条目路由聚集可以减少路由通告的数量，路由表象的代价、计算的代价。

  • 路由通告：路由器使用路由通告将其所知道的网络路径或路由信息告知其他路由器，从而使得整个网络中的设备都能了解如何到达不同的目的地网络。

  • 路由算法：计算和确定数据包从源设备到目标设备最佳路径的规则或方法。

eg:192.168.0.0/24 192.168.1.0/24 192.168.2.0/24 192.168.3.0/24，通过网路通告，告诉上一级的路由器”我是你的下一条，把这个网段的信息交给我” 路由器通过路由聚集，可以将它们聚集成： 192.168.0.0/22 。这样子网的数据包可以通过汇集的方式一起通过路由器发送；到来的数据包也可以通过匹配的方式发给某个子网，从而可以减少网络压力。

NAT

​ NAT：network address translation 将内部网络的私有IP地址转换为公共IP地址。 首先内网地址不能用于路由，NAT能够将多个私有IP地址映射到一个公共IP地址上。实现了：节省IP地址：通过地址转换，多个设备共享一个公共IP地址，节省了宝贵的IPv4地址。隐蔽性：内网设备的私有IP对外网不可见，提高了安全性。

工作原理:NAT通常通过修改数据包的IP头部来实现地址转换。主要有三种常见的NAT类型：

  1. 静态NAT：每个内部IP地址都有一个固定的公共IP地址映射关系。当一个设备发送数据包时，NAT路由器会将其私有IP地址替换为映射的公共IP地址。这个映射是固定的，不会发生变化。
  2. 动态NAT：类似于静态NAT，但是公共IP地址的映射是动态分配的。当内部设备需要访问互联网时，NAT路由器会从一个公共IP地址池中选择一个IP地址映射给该设备。这个映射关系可能会变化。
  3. 端口地址转换（PAT）：也叫做“重用NAT”或“对多个设备使用一个公共IP”。这种方式是最常见的NAT形式，在家庭或小型企业网络中使用。当多个内部设备通过同一个公共IP地址访问互联网时，NAT路由器会根据源端口号来区分不同的会话。每个内部设备的IP地址和端口号都会映射到一个公共IP地址的不同端口上。

IPV6: 2^128 个ip地址，可以为每一个主机分配ip地址，目前并没有大规模使用，采用

  • 将ipv6数据包封装在ipv4数据包内向外发送
  • 在一个ipv6内部使用没有问题，但是ipv6不能与ipv4通信，采用上述方法可以『跨越』。
  • 愿景：ipv6的设备越来越多，最终实现平滑过渡。

SDN（软件定义网络，Software Defined Networking）是一种网络架构，它通过将网络的控制层（控制平面）和数据转发层（数据平面）分离，从而提供更高的灵活性和可编程性。它的核心思想是将传统网络设备中的控制逻辑从硬件中提取出来，集中到一个集中式的控制器上，这样网络管理人员可以通过软件来动态地配置和优化网络。

  • 传统路由：控制平面和路由平面紧密耦合，即路由器直接负责路由和转发。
    • eg：厂商生产的操作系统，软件，硬件必须成套购买。不同的路由器可能交互有些问题。
  • SDN 工作流程
    • 控制平面与数据平面分离：
      • 在传统网络中，路由器和交换机的控制平面和数据平面是紧密耦合的。而在 SDN 中，数据平面（即实际的数据转发）由网络设备执行，而控制平面则由一个或多个集中式控制器管理。
    • SDN 控制器：
      • 控制器是 SDN 的核心，负责处理整个网络的流量管理决策。控制器通过与网络设备（如交换机、路由器）通信来管理网络流量，它会根据预设策略和网络的实时状态来决定如何转发数据。
    • 流表与数据流：
      • 网络设备（如 OpenFlow 交换机）根据控制器下发的流表来处理和转发数据。流表是一个包含一组规则的数据结构，每一条规则（流表项）都包含条件（如匹配字段）和行动（如转发、丢弃、修改等）。
    • OpenFlow：
      • OpenFlow 是 SDN 中常用的协议，它定义了控制器与数据平面设备（如交换机）之间的通信方式。通过 OpenFlow，控制器能够管理设备的流表，控制数据包的转发路径。
      • 数据平面抽象：在 OpenFlow 中，网络设备的数据平面是通过流表来抽象的。每个数据包进来时，OpenFlow 交换机会通过流表的匹配项来决定如何处理数据包。
      • 流表项：每个流表项都包含多个字段：（额外补充）
        1. 匹配条件（Match Fields）：指定该流表项匹配的条件，如源IP、目标IP、协议类型、端口号等。
        2. 动作（Action）：当数据包匹配到该流表项时，需要执行的动作，如转发到某个端口、修改数据包内容、丢弃数据包等。
        3. 计数器（Counters）：用于统计与流表项相关的数据包数量和字节数。
        4. 优先级（Priority）：用于指定流表项的匹配优先级。匹配条件更精确的流表项优先级更高。
        5. 过期时间（Timeout）：流表项的有效期，超时后会被删除。
    • 在 SDN 中，流表替代了传统路由器中的路由表，当一个数据包到达设备时，设备会查看流表，找到与该数据包匹配的流表项。然后按照流表中的指示转发数据包。这可以是简单的转发到一个端口，或者更复杂的操作，如修改数据包内容、转发到多个端口等。
  • SDN的工作模式下，传统网络设备的 功能 和 职责 进行了一定的拆分与重构，被丰富了更多功能 。
