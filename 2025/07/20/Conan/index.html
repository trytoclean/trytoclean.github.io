conan的简要介绍

Conan， 一款面向 C 和 C++ 开发人员的软件包管理器

它可在包括 Windows、Linux、OSX、FreeBSD 等在内的所有操作系统上运行，并可面向任何平台，包括桌面、服务器以及移动（Android 和 iOS）交叉编译，以及嵌入式和裸机设备。它可与其他工具（如 Docker、MinGW、WSL）以及所有构建系统（如 CMake、MSBuild、Makefiles、Meson、SCons）集成。它甚至可以与任何专有构建系统集成。

不仅二进制文件不同，构建配置也不同，包括不同的架构、编译器、编译器版本、运行时环境、C++ 标准库等等。当某个配置没有可用的二进制文件时，可以按需从源代码构建。Conan 可以使用相同的命令和流程在每个平台上创建、上传和下载二进制文件，从而节省大量的开发和持续集成时间。

使用方法：

  1. 初次使用conan 请使用 conan profile detect –force 。 此命令会根据环境检测操作系统、构建架构和编译器设置。默认情况下，构建配置会设置为 Release 。生成的配置文件将存储在 Conan 主文件夹中，名称为 default

  2. 使用**conan search **查找你所需要的包在 remote center是否提供

  3. 在你的项目的顶层目录添加conanfile.txt （或者.py），添加需要的package和generators（generator使用官方提供的use case即可）

  4. 在shell中输入conan install . --build=missing （解释：conan会按照file中的要求去找package，如果没有匹配到二进制文件，则会拉代码从头构建

查找原理，conan会根据操作系统，编译器信息（查看conan profile）生成一个唯一的哈希值。如果本地信息和remote center的哈希值一样，就会直接使用由conan准备的package，如果不能匹配，就会拉代码从头构建。

  1. 如果成功，则会在根目录生成build 文件夹。

  • 对于clangd 使用者

    需要在generator 目录下的CMakePresets.json 中cacheVariables 下添加

    “CMAKE_EXPORT_COMPILE_COMMANDS”: “ON”

    conan默认不会生成compile_commands.json ，而clangd需要这个，不然会出现:’libavformat/avformat.h’ file not found 的问题，当你可以找到定义，配置成功。
